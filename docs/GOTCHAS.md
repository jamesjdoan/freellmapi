# GOTCHAS

**Purpose:** Genuinely non-obvious landmines only. Two-minute read maximum.

---

- Quota tests that insert `provider_quota_state` directly must call `invalidateKeyQuotaHeadroom(platform)`. Production writes already invalidate this five-second routing cache through `recordQuotaObservation`.
- **OpenCode Zen's free tier is gated per MODEL, not per caller, and the gate moves.** Most free ids answer `403 FreeTierError: "OpenCode's free tier can only be used from within OpenCode"` to any direct call, whatever the key or headers (confirmed 2026-09-20, and again 2026-10-07/08 for `nemotron-3-ultra-free` and `fledge-alpha-free`). But on 2026-10-08 `space-bunny-free` answered `200` with tool calls and image input on the same key. So test each id; never conclude from one. The built-in `opencode` platform is catalogue-managed (`POST /api/keys/discovered-models` refuses it, and its 7 rows stay off), so the reachable model is registered as a **custom endpoint**: key #35, `https://opencode.ai/zen/v1`, model `space-bunny-free`. Every other id Zen listed that day (85) is tombstoned on that endpoint so the daily custom sync cannot add the 403 ones; a NEW id Zen lists later is not tombstoned and will be registered by the sync if it ends in `-free`. The gated models remain usable through the OpenCode client itself (`atelier/scripts/clifree-ask.sh -m opencode:<id>`), which satisfies the rule rather than dodging it.
- **Re-probed the whole Zen free roster on 2026-10-09: `$0` pricing on a model's page does not mean the endpoint serves you.** Of the six ids OpenCode lists at $0 (`space-bunny-free`, `step-5-preview-free`, `exo-free`, `ling-3.1-flash-free`, `mimo-v2.6-flash-free`, `nemotron-3-ultra-free`), exactly one answered on key #35 that day: `space-bunny-free` → 200. `exo-free` → `410 Model exo-free has been deprecated`. The other four → `403 FreeTierError` caller-gate. A published price of zero is a catalogue fact, not reachability; only a probe settles it. `step-5-preview-free` had been missed by the tombstone sweep and is now tombstoned too (86 on that endpoint). When probing by hand, decrypt exactly as `lib/crypto.ts decrypt()` does — `utf8` output **and** `final()`, which is what verifies the GCM auth tag. Omitting `final()` and/or reading `base64` yields garbage, and the endpoint answers a bare `401 Invalid API key.` that looks exactly like a revoked credential.
- **`space-bunny-free`'s API path closed on 2026-10-12; its CLI path did not. Do not conflate the two.** Three direct calls to key #35 that day all returned `403 FreeTierError`, the same caller-gate that had held the other ids since September — so the one id that had escaped the gate for four days was finally caught by it. Measured the same day, `clifree-ask.sh -m opencode:space-bunny-free` answered normally (`in 19673 out 5`, cost not reported). This is the gate's stated meaning, not a contradiction: the credential is valid and the refusal is about **where the call originates**, so the vendor's own CLI satisfies it while a direct API call cannot. FreeLLM routes by API call, so `space-bunny-free` is unusable as a FreeLLM route from 2026-10-12 onward while remaining fully usable through `clifree`/`jd-clifree`. Check whether a Zen id still serves FreeLLM (API) and whether it serves clifree (CLI) as two separate questions.
- **`account_blocked` was renamed `access_denied` (2026-09-20).** 403/402 covers plan limits, ended promotions, region blocks *and* caller-origin rules; only the last is what OpenCode does, and none of them mean the account is blocked. `20260920_000001_rename_access_denied.ts` rewrites stored history rows so a grep for the feature finds its past too.
- **`models.paid_input_per_m` is NOT "this route bills you". Never prune or route on it.** `src/db/model-pricing.ts` documents it as the *paid-equivalent* list price, used only by the analytics "Est. savings" stat. Whether a request spends money is decided by `consumesPaidBalance()` (`src/services/provider-quota.ts`): only `openrouter`, `anyapi` and `unorouter` routes without a `:free` suffix bill, and `paid-balance-guard` blocks those. On 2026-10-08 a "free-only" prune read the column as billing and disabled free-tier routes that cost nothing — among them `groq/openai/gpt-oss-20b` (369/385 over 14 days, 649 ms p50). Reversed on 2026-10-12 by diffing against the pre-prune backup: 13 routes restored, each one keyed, servable under its key's scope, and free per `consumesPaidBalance`.
- **The curation applier cannot place custom-endpoint routes, and running it switches them off.** `scripts/apply-routing-curation.ts` looks models up `WHERE endpoint_scope = ''`, so every custom route (the 44 Inferera models on key #34) is invisible to it, and its rule "switch off every chain row the spec does not name" then disables them all. That is why `data/routing-curation.ts` drifted from the live chains: the custom routes were added by hand. A dry run on 2026-10-12 showed it would route disabled models and strip every live custom route. Until the applier learns endpoint-scoped routes, chain membership is changed in `profile_models` directly — do not run `--apply`.
- **Map a clifree route on the fleet panel, not in Keys.** Keys only lists routes that have a FreeLLM model row, and 20 of the 25 `opencode:`/`cline:` routes have none, so most of them cannot be mapped there at all. The fleet panel (Analytics → Compare models → Free CLI fleet → Mapped to) has the same picker with a **closest match** tick and writes the same `aa_model_link` row, under platform `opencode` or `cline`. Since 2026-10-12 `clifree-rank.sh` reads `manual` and `proxy` links first and applies the same proxy deltas as `services/analysis.ts nudge()`, falling back to name matching only when nothing is recorded. Before that the panel saved to a second store, `settings.clifree_fleet_links`, which had no proxy option and which the ranker never read. A remap there changed the panel and nothing else, and on the day the two were unified they disagreed about `space-bunny-free` (panel: no counterpart; link table: `glm-5-3-flash` proxy). Migration `20261012_000001` moved the settings entries across, with an existing link-table decision winning. **A "no counterpart" mapping does not reach the ranker:** its query filters `aa_slug IS NOT NULL`, so it falls back to a name guess for that route.


## 2026-10-04 — analytics windows, two charts reading "the same" for different reasons

- **"The 30d and 90d charts don't re-render" was a data bug wearing a render bug's clothes.** The chart redrew every time; it drew identical data. Two independent causes, and checking only one leaves it broken. (1) `/timeline` picked its interval with `range === '24h' ? 'hour' : 'day'`, so every window past a day drew one point per day — past 30 days of retention, 30d and 90d returned the **same 31 bucket labels**, byte-identical. (2) `HOURLY_RETENTION_DAYS` was 30 while the toggle already offered 90d, so "90 days" was reading a 30-day window. Diagnose this by comparing the aggregate directly rather than by watching the UI: `SELECT COUNT(*), COUNT(DISTINCT strftime('%Y-%m-%d', hour)), SUM(total_requests) FROM request_hourly WHERE hour >= datetime('now','-30 day')` and the same at `-90 day`. If the bucket counts are equal, the interval is the cause; if the request sums are equal, the retention is.
- **An hourly bucket is keyed by its FIRST second, so the aggregate's upper bound must not be ceiled.** `since` IS floored — a rolling 24h window opens mid-hour and dropping that partial hour understates it. `until` is NOT ceiled: a bucket at exactly `until` holds only time at or past the bound, so rounding it up to the next hour pulls in a whole bucket the window excludes. Measured on a copy of the live DB: a custom window ending at midnight counted 248 requests from the following hour. The bug is invisible in every preset test (their `until` is "now", where the next hour is empty) and only shows on a **custom** window with a clean midnight boundary.
- **Joining `api_keys` to `requests` makes bare `platform` ambiguous.** `api_keys` has its own `platform` column, so `SELECT platform` becomes `ambiguous column name` the moment the endpoint-scoped provider filter needs that join — which is every analytics endpoint now. Qualify as `r.platform`. It surfaced as an HTML error page rather than a 500, because the failure was at query-preparation time in a route that had already sent no response.
- **A filter dropdown must not read the filtered list.** Selecting `groq` from the provider filter makes the filtered `/by-platform` response contain only `groq`, so if the dropdown reads it, every other provider disappears and the filter becomes a one-way door. The provider and model option lists are fetched **unfiltered at 365d** — the same idiom the device tabs already used for exactly this reason (`AnalyticsPage.tsx`, `providerOptions` / `modelOptions` / `knownDevices`). The **panel below** does read the filtered list; that is the point of filtering. Conflating the two is how this bit twice.
- **A query-string builder, not a per-call-site template, is what keeps panels agreeing.** The range used to ride eight hand-built `?range=${range}${deviceParam}` URLs, so a new filter dimension meant eight edits and the one that got missed would silently disagree with the rest — which is what happened when status/provider were scoped to `/requests` alone. `windowParams()` composes the window and all three filters in one place, and it is also the query-key material, so react-query caches each combination on its own.
- **recharts INFERS the X-axis type, and from two data points it infers a NUMERIC one.** The symptom is an axis with no labels: the X axis renders `2 empty tick groups`, and the date strings you *do* see ("Sept 26", "Oct 26") turn out to be Y-axis ticks — confirmed by walking `.recharts-xAxis` and finding zero `.recharts-cartesian-axis-tick-value` descendants while `document.querySelectorAll('.recharts-text')` returns them. It bites exactly when a window is long and traffic is short: 180d/365d bucketed by MONTH over a young install gives two buckets. Fix by stating `type="category"` on the `XAxis`, which invents no data and restores the labels. A gap-filling helper is NOT the fix for this — adjacent buckets have no gap to fill, so it returns the same two rows (this cost an hour).
- **Selecting a preset in the browser needs a fresh tab after a rebuild, and the served bundle is proof.** A rebuilt page kept showing the old toggle because the tab had cached the document. Check what is actually shipped before debugging the component: `curl -s http://127.0.0.1:3001/ | grep -o '/assets/index-[A-Za-z0-9_-]*\.js'` gives the asset name, and grep THAT for a marker string. Beware two false negatives: the minifier emits `` type:`category` `` with backticks, so `grep 'type:"category"'` returns 0 on a bundle that has it; and this page's charts live in the same asset but render through portals, so a selector that looks right in the source returns nothing at runtime.

## 2026-10-04 — wrong Tailscale host, sync pushing upstream, an "ok" that is a refusal

- **An hourly reporter can fail 212 times on one wrong hostname.** The MBP's `clifree-report.sh` reported `runs = 212`, `last exit code = 1`, every log line `FreeLLM container unreachable on jamesdoan@mac-studio-2.tailf2c2be.ts.net`. Cause: this Studio's Tailscale name is `mac-studio.tailf2c2be.ts.net`; its hostname is "Mac Studio (2)", and the stray `-2` came from there. The timer, network and script were all fine. Diagnose from `clifree-report-timer.sh status` → the last log line NAMES the unreachable host. The fix is the host, in TWO variables (`CLIFREE_REPORT_HOST`, `CLIFREE_BENCH_HOST`), and `clifree-report-timer.sh:83` copies them into the launchd plist AT INSTALL TIME — so exporting and re-installing is what makes it stick; exporting alone, or installing before exporting, leaves the old value in place.
- **`code-sync.sh` pushed freellmapi's 33 commits at the UPSTREAM project.** It hardcoded `push origin`, but freellmapi's `origin` is `tashfeenahmed/freellmapi` and its work lives on `fork`. The push was refused (33 commits sat unpushed, tool printed a bare `PUSH-FAIL`) — the refusal is the only reason nothing leaked; had upstream accepted, private work would have been published there. Fixed on the MBP first in `bd570ac` (`repo_remote()`, which also covers the fetch path); local `6ff608b` was redundant. Symptom to recognise: a repo that is permanently `ahead=N` in `status` while a direct `git push fork` works. **A `PUSH-FAIL` with no reason means diagnose the tool, not the repo.**
- **A 429 "Request too large ... on output tokens per minute" is the size fix WORKING.** Groq answering `Limit 1000, Requested 1915` on OTPM means v0.13.3's output-cap learning recognised the phrasing: the model is skipped for THAT request, not benched for the day. A single such line in the logs is expected traffic, not a fault — the thing to alarm on is the same model repeated.
- **`git reset --hard` on custodia destroys an unpushed handoff.** The local checkout carried 88 lines of uncommitted `config/handoff.md` + `changelog.md` (a real machine session record) that `origin` did not have. Stash FIRST, then reset, then `stash pop`. The pop then conflicts with the other machine's committed wrap of the same files — resolve by keeping BOTH sides, because the handoff is append-only and picking one loses that machine's record. Drop the stash only after confirming its content is in HEAD.

## 2026-10-01 — upstream merges, dev-server proxying, two-stage buttons

- **`git merge-tree --write-tree <old base> HEAD` is always clean, and proves nothing.** The previous release tag is already an ancestor of the extension branch, so merging it is a no-op. The v0.13.3 pre-flight ran it, reported zero conflicts, and the real `git merge --no-ff v0.13.3` then stopped on 65 files. Measure against the NEW tag: `git merge-tree --write-tree vX.Y.Z HEAD` — a non-zero exit lists the conflicts.
- **A clean text merge can still fail to compile.** v0.13.3 deleted `estimateTokens` from `server/src/routes/anthropic.ts`; the extension had added a new caller of it in a region git merged without complaint. Only `npx tsc --noEmit -p tsconfig.json` in `server/` caught it (`TS2304: Cannot find name 'estimateTokens'`). Typecheck both packages after every upstream merge, before the test suite. Also check the invariant `comm -3 <(git diff --name-only <old tip> <merge> | sort) <(git diff --name-only <old base tag> vX.Y.Z | sort)` is empty.
- **Upstream tests can encode behaviour the extension changes on purpose.** After v0.13.3 two upstream tests failed with nothing broken: `keyless-bearer-1331.test.ts` captured the LAST fetch, which is the extension's unauthenticated control probe (`endpointEnforcesAuth`), not the credentialed request; `fallback-loop.test.ts` expected a Gemini per-minute 429 to bench for 90s, where `e18d2c92` honours the stated 17s. Read the extension commit that owns the behaviour before "fixing" either side — the fix was the test, not the code.
- **`PORT=3002 npx vite` makes the dev proxy call itself.** `client/vite.config.ts:8` reads `PORT` for the `/api` proxy TARGET, so overriding it to move the dev server sends `/api` back to the dev server: every call answers 502 and the page shows "Can't reach the server". Leave `PORT` alone and move only the listener: `npx vite --port 3002 --strictPort` (`.env` keeps the target at 3001). Two more traps on the same path: Vite binds `[::1]` only, so `127.0.0.1:3002` is refused and `localhost:3002` works; and the dashboard token is per-origin `localStorage`, so copy `freellmapi_dashboard_token` from the `127.0.0.1:3001` tab into the dev tab before loading it.
- **`ConfirmButton` needs two clicks, and one click does nothing visible.** The first click only arms it (label flips, e.g. to `Change routing` or `Mark as read`); the second, within 3s, fires `onConfirm`. Browser automation that clicks once captures no request and reads like a broken handler. Click, wait for the armed label to appear, then click that label.

## 2026-09-21 — shared package, the three enable switches, derived device labels

- **`@freellmapi/shared` ships no JavaScript — a value import from it crash-loops the container.** Its `package.json` main is `./types.ts`, which is never compiled into the image, so `import { X } from '@freellmapi/shared/types.js'` dies at boot with `ERR_MODULE_NOT_FOUND: /app/node_modules/@freellmapi/shared/types.js` while `import type` from the same path works fine — type imports erase, so nothing ever needed the runtime file. Every pre-existing server import from shared is a type import, which is why this had never surfaced. Runtime constants shared by both halves go in `server/src/data/*.ts` (compiled into `server/dist`) with the client keeping its own copy; `server/src/data/extension-registry.ts` documents this at the top of the file and is the precedent to follow.
- **Three separate layers claim to control `models.enabled`, and the one that wins is invisible in the UI.** They are the catalogue flag (`models.enabled`), chain membership (`profile_models.enabled`), and a saved local override (`model_overrides.overrides_json.enabled`). `applyModelOverrides()` runs after every catalogue upsert, so a stale `{"enabled":1}` override silently re-enables a model on every sync: a hand-written `UPDATE models SET enabled=0` was reverted on the next container restart, twice, before the override layer was found. `catalog-sync.ts` preserves a local disable but does not clear an override. Check `SELECT * FROM model_overrides WHERE platform=?` before concluding a disable "did not stick".
- **The Analytics device label is derived at query time and the stored column disagrees with it.** `requests.client_agent` reads `unknown` for 22,544 of 22,559 rows, but the dashboard correctly shows Mac Studio and MacBook Pro because `DEVICE_SQL` (`routes/analytics.ts:112`) maps `client_user_agent LIKE 'omp-studio%'` / `'omp-mbp%'` at SELECT time. Querying the stored column to ask "is device tracking working" gives the opposite of the truth. Note the third arm: bare `omp/%` is attributed to Mac Studio by an explicit operator ruling, so the Studio's history absorbs untagged MacBook traffic from before tagging existed.
- **The client bundle is baked into the image, so `npm run build` on the host changes nothing the browser sees.** Only `freellmapi-data` is mounted; `client/dist` is not. A UI change verified by a passing host build will be invisible until `docker compose build && docker compose up -d`. Confirm with `curl -s http://127.0.0.1:3001/ | grep -o '/assets/index-[A-Za-z0-9_-]*\.js'` and grep that asset for a string unique to the change — the served filename hash changes when the new bundle ships. Related: nothing typechecks the branch between deploys, and a one-word compile error (`latencyMs` for the `elapsedMs` parameter, `lib/request-log.ts:93`, introduced 2026-09-11 in `c67f0857`) blocked every image build for ten days without anyone noticing. **Timestamps do not substitute for the grep (2026-09-29):** an image built three days after the source files' mtimes was reported as "covering" the uncommitted change, and the served `index-*.js` held `chainNoRoutable` 0 times — the image had been built from a tree without it. Only `docker exec freellmapi-freellmapi-1 sh -lc 'grep -c <unique-string> /app/client/dist/assets/index-*.js'` answers the question.

## 2026-09-07 — deploy verification, provider errors, quota estimators

- **`docker compose up -d 2>&1 | tail -1` reports success on a failed deploy.** The exit status comes from `tail`, so a port conflict prints "deployed" while the container sits in `Created` — and `restart: unless-stopped` never starts one that has not run, so the gateway stays down through reboots. Never pipe a command whose status you rely on. A health check alone cannot prove a deploy landed either: a stale container answers healthy for the *previous* build. `scripts/deploy.sh` asks the container whether it is serving (`curl -w '%{http_code}'`; `401` is the healthy answer) and compares the running image digest to the tag just built.
- **`compose up -d` races itself on the host port** — it removes the old container and rebinds before Docker releases the port (`bind: address already in use`, then success a second later). `scripts/deploy.sh` retries with backoff; the race is exercised against a stub `docker` on `PATH` in `scripts/deploy.test.mjs`.
- **A 401 does not always mean the key is bad.** OpenCode Zen answers `401: Model north-mini-code-free is not supported` — the body blames the *model*. `isKeyAuthError` read that as a credential failure and condemned the whole key, dropping the provider from routing while 6 of its 11 models worked. `isModelScopedAuthError` (`src/lib/error-classify.ts`) now makes a 401/403 naming the model model-fatal; a bare 401 with no body stays key-fatal.
- **`origin` in this repo is `tashfeenahmed/freellmapi` — upstream, not yours.** Your fork is the `fork` remote. `git push origin main` would put ~68 local commits into someone else's repository. Run `git remote -v` before any push here.
- **Suppressing repeated quota observations broke two estimators that were correct in isolation.** They use row spacing to tell "idle" from "the poller was down"; dedupe removed 82.6% of rows and that distinction with them, so a reset after a quiet stretch was discarded as unobserved. An unchanged reading is now recorded once the series has been quiet 15 min — deliberately shorter than the 20-min boundary bracket.
- **A polling gap that hides a reset inflates a derived allowance several-fold.** Read 25%, then 10% five hours later: the pool actually refilled and burned 90%, while the difference claims 15% — spend then divides by a sixth of the real fraction. Runs end at any gap > 30 min, and a reset is only *timed* when the readings bracketing it are within 20 min. Corollary: three "observed resets" on live data turned out to be two polling artefacts.
- **Three providers report the metric `credits` in incomparable units** — OpenRouter in cents of account balance, Ollama as a fraction of an allowance scaled to 10,000, and Radeon (upstream v0.9.6) in whole USD on `x-ratelimit-*-user-daily-usd`. Formatting the first two as money produced `$82.90` against a fabricated `$100.00` ceiling. Observations carry a `unit` column; only `cents` renders as currency, so a header that arrives in dollars declares `unit: 'cents', scale: 100` on its `HeaderSpec` and is converted at parse. A new currency unit would be a third denomination every consumer has to learn — convert instead.
- **`finish_reason === 'length'` exempts a failure from the cooldown bench — and a reasoning model can spend a 215K-token prefill on hidden reasoning and emit nothing.** The same request retried three times at ~100K tokens each, metered as 1 request / 0 tokens. Only the *streaming* path shows it; non-streaming folds reasoning into `content`, which is why it looked model-specific. The exemption is now priced by `wastedInputTokens` and lifts once cumulative waste exceeds the budget, and failed attempts meter their tokens.
