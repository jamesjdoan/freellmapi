# GOTCHAS

**Purpose:** Genuinely non-obvious landmines only. Two-minute read maximum.

---

- Quota tests that insert `provider_quota_state` directly must call `invalidateKeyQuotaHeadroom(platform)`. Production writes already invalidate this five-second routing cache through `recordQuotaObservation`.
- **OpenCode Zen's free tier cannot be reached from FreeLLM at all, and no key fixes it.** A direct call answers `403 FreeTierError: "OpenCode's free tier can only be used from within OpenCode"`. Confirmed 2026-09-20 against `https://opencode.ai/zen/v1/chat/completions` with a freshly issued key: the credential is valid and the account is in good standing — the refusal is about *where the call originates*, so swapping keys, re-authenticating or adding headers changes nothing. Its 11 catalogue rows stay unroutable, and the provider's verdict is `access_denied`, not `key_rejected`. The models are still usable through the OpenCode client itself; `atelier/scripts/opencode-ask.sh` wraps `opencode run` for that, which satisfies the rule rather than dodging it.
- **`account_blocked` was renamed `access_denied` (2026-09-20).** 403/402 covers plan limits, ended promotions, region blocks *and* caller-origin rules; only the last is what OpenCode does, and none of them mean the account is blocked. `20260920_000001_rename_access_denied.ts` rewrites stored history rows so a grep for the feature finds its past too.

## 2026-09-23 — curation drift, probes that prove less than they say, benchmark sources

- **The container's `apply-routing-curation.js` applies the DEPLOYED spec, not the one in your checkout.** Editing `server/src/data/routing-curation.ts` and mirroring the change onto the live chains through `POST /api/fallback/membership` leaves the image's compiled spec one version behind, so `node server/dist/scripts/apply-routing-curation.js --apply` in the container would revert the live chains to the old spec. Deploy first, then confirm `docker compose exec -T freellmapi node server/dist/scripts/apply-routing-curation.js` prints `0 switched off`. To check a spec before deploying, back up the live DB (`better-sqlite3` `.backup()` inside the container, `docker compose cp` it out) and dry-run `npx tsx src/scripts/apply-routing-curation.ts --db <copy>` from `server/`.
- **Chain positions must be contiguous.** Removing a route from the middle of a chain fails `routing-curation.test.ts` › "numbers every chain contiguously from 1" (`Fast-Lane priorities are not 1..8: expected [1…7, 9]`). Renumber the routes after it. Removing a chain's tail needs nothing.
- **The vision probe passes any non-empty reply, so it cannot tell a describer from a parser.** `probeModelVision` records `ok` on any answer. Confirm a Vision candidate with a describe prompt against `PROBE_IMAGE_DATA_URL` (an 8×8 red PNG) and read the text: `diffusiongemma-26b-a4b-it` answered "The image is red.", where `nemotron-parse-2.0` had passed the probe and could not see.
- **`POST /api/keys/model-health/probe` has no paid-balance guard.** `runProbe` calls `provider.chatCompletion` directly, so it bills whatever id it is given. It was safe on 2026-09-23 only because every scoped OpenRouter id ended in `:free`. Check that suffix before probing a single-credential provider.
- **Do not export `FREEAPI_DB_PATH` for `npm test`.** Server tests open `:memory:`, and `config.test.ts` › "returns sensible defaults" asserts `dbPath` is null, so the override fails that test and the chained `test -w cli` and `test -w client` never run.
- **Artificial Analysis's free tier returns three evaluation scores, whatever its docs example shows.** Across all 673 models (4 pages) `evaluations` holds only `artificial_analysis_intelligence_index`, `_coding_index` and `_agentic_index`. `mmlu_pro`, `gpqa`, `hle` and the rest from the docs example are absent as keys, not null, and there is no APEX field. Mercor's APEX leaderboards embed their full results in each page's `__NEXT_DATA__` (`props.pageProps.leaderboardData`, `readyBenchmarks`). `robots.txt` allows `/apex/` but disallows `/_next/data/` and `/api/`.

## 2026-09-22 — the build is the only type gate, and stale-bundle verification

- **`npx tsc --noEmit` in `client/` passes things the Docker build's typecheck rejects.** Three defects cleared the local run this session and were caught only by `docker compose build`: a stray comma making a ternary a syntax error, a temporal-dead-zone read (`dirty` referencing `query`/`sort` above their `useState` lines), and an invalid prop (`collisionPadding` on a `PopoverContent` that forwards only `align`/`side`/`sideOffset`). Treat the local run as a smoke test and the image build as the gate: `docker compose up -d --build 2>&1 | grep -iE "error TS"`.
- **A failed build leaves the OLD container running and still prints `Started`.** `docker compose up -d --build` reports the existing container starting when the image build failed, so the dashboard keeps serving the previous bundle. Three consecutive verifications ran against a stale bundle before the `error TS` line was noticed — the edits *had* applied, the image was simply never built. Grep the build output, and confirm `Recreated` appears, not just `Started`.
- **`apply-translations.mjs --fill-english` fills MISSING keys only; it never updates a CHANGED one.** Editing an English string leaves 59 locales holding the previous text, and `check:i18n` then fails them as "text in the wrong language" — 52 errors from two edited hints. The script reports `filled 0 key(s)` and reads like a no-op success. After changing English text, overwrite that key across the locales explicitly.
- **OpenCode Zen IS a registered FreeLLM provider — only its FREE tier is unreachable.** `server/src/providers/index.ts:265` registers `platform: 'opencode'` against `https://opencode.ai/zen/v1`, and it works with an account key. The 403 above is the promotional free roster refusing callers outside the OpenCode client. "OpenCode cannot be a FreeLLM provider" is false and was briefly asserted in a skill body; the true claim is narrower.
- **React's `autoFocus` scrolls the page when the element sits in a portalled popup.** React implements it as a bare `focus()`, and scroll-into-view fires before the popup is positioned — opening the Compare mapping combobox jumped the document from y=4485 to 0. Use `ref={el => el?.focus({ preventScroll: true })}`. Found only by hooking `HTMLElement.focus` in an init script BEFORE navigation; a hook installed after load watching `scrollTo`/`scrollIntoView` caught nothing and made the bug look intermittent.

## 2026-09-21 — shared package, the three enable switches, derived device labels

- **`@freellmapi/shared` ships no JavaScript — a value import from it crash-loops the container.** Its `package.json` main is `./types.ts`, which is never compiled into the image, so `import { X } from '@freellmapi/shared/types.js'` dies at boot with `ERR_MODULE_NOT_FOUND: /app/node_modules/@freellmapi/shared/types.js` while `import type` from the same path works fine — type imports erase, so nothing ever needed the runtime file. Every pre-existing server import from shared is a type import, which is why this had never surfaced. Runtime constants shared by both halves go in `server/src/data/*.ts` (compiled into `server/dist`) with the client keeping its own copy; `server/src/data/extension-registry.ts` documents this at the top of the file and is the precedent to follow.
- **Three separate layers claim to control `models.enabled`, and the one that wins is invisible in the UI.** They are the catalogue flag (`models.enabled`), chain membership (`profile_models.enabled`), and a saved local override (`model_overrides.overrides_json.enabled`). `applyModelOverrides()` runs after every catalogue upsert, so a stale `{"enabled":1}` override silently re-enables a model on every sync: a hand-written `UPDATE models SET enabled=0` was reverted on the next container restart, twice, before the override layer was found. `catalog-sync.ts` preserves a local disable but does not clear an override. Check `SELECT * FROM model_overrides WHERE platform=?` before concluding a disable "did not stick".
- **The Analytics device label is derived at query time and the stored column disagrees with it.** `requests.client_agent` reads `unknown` for 22,544 of 22,559 rows, but the dashboard correctly shows Mac Studio and MacBook Pro because `DEVICE_SQL` (`routes/analytics.ts:112`) maps `client_user_agent LIKE 'omp-studio%'` / `'omp-mbp%'` at SELECT time. Querying the stored column to ask "is device tracking working" gives the opposite of the truth. Note the third arm: bare `omp/%` is attributed to Mac Studio by an explicit operator ruling, so the Studio's history absorbs untagged MacBook traffic from before tagging existed.
- **The client bundle is baked into the image, so `npm run build` on the host changes nothing the browser sees.** Only `freellmapi-data` is mounted; `client/dist` is not. A UI change verified by a passing host build will be invisible until `docker compose build && docker compose up -d`. Confirm with `curl -s http://127.0.0.1:3001/ | grep -o '/assets/index-[A-Za-z0-9_-]*\.js'` and grep that asset for a string unique to the change — the served filename hash changes when the new bundle ships. Related: nothing typechecks the branch between deploys, and a one-word compile error (`latencyMs` for the `elapsedMs` parameter, `lib/request-log.ts:93`, introduced 2026-09-11 in `c67f0857`) blocked every image build for ten days without anyone noticing.

## 2026-09-07 — deploy verification, provider errors, quota estimators

- **`docker compose up -d 2>&1 | tail -1` reports success on a failed deploy.** The exit status comes from `tail`, so a port conflict prints "deployed" while the container sits in `Created` — and `restart: unless-stopped` never starts one that has not run, so the gateway stays down through reboots. Never pipe a command whose status you rely on. A health check alone cannot prove a deploy landed either: a stale container answers healthy for the *previous* build. `scripts/deploy.sh` asks the container whether it is serving (`curl -w '%{http_code}'`; `401` is the healthy answer) and compares the running image digest to the tag just built.
- **`compose up -d` races itself on the host port** — it removes the old container and rebinds before Docker releases the port (`bind: address already in use`, then success a second later). `scripts/deploy.sh` retries with backoff; the race is exercised against a stub `docker` on `PATH` in `scripts/deploy.test.mjs`.
- **A 401 does not always mean the key is bad.** OpenCode Zen answers `401: Model north-mini-code-free is not supported` — the body blames the *model*. `isKeyAuthError` read that as a credential failure and condemned the whole key, dropping the provider from routing while 6 of its 11 models worked. `isModelScopedAuthError` (`src/lib/error-classify.ts`) now makes a 401/403 naming the model model-fatal; a bare 401 with no body stays key-fatal.
- **`origin` in this repo is `tashfeenahmed/freellmapi` — upstream, not yours.** Your fork is the `fork` remote. `git push origin main` would put ~68 local commits into someone else's repository. Run `git remote -v` before any push here.
- **Suppressing repeated quota observations broke two estimators that were correct in isolation.** They use row spacing to tell "idle" from "the poller was down"; dedupe removed 82.6% of rows and that distinction with them, so a reset after a quiet stretch was discarded as unobserved. An unchanged reading is now recorded once the series has been quiet 15 min — deliberately shorter than the 20-min boundary bracket.
- **A polling gap that hides a reset inflates a derived allowance several-fold.** Read 25%, then 10% five hours later: the pool actually refilled and burned 90%, while the difference claims 15% — spend then divides by a sixth of the real fraction. Runs end at any gap > 30 min, and a reset is only *timed* when the readings bracketing it are within 20 min. Corollary: three "observed resets" on live data turned out to be two polling artefacts.
- **Three providers report the metric `credits` in incomparable units** — OpenRouter in cents of account balance, Ollama as a fraction of an allowance scaled to 10,000, and Radeon (upstream v0.9.6) in whole USD on `x-ratelimit-*-user-daily-usd`. Formatting the first two as money produced `$82.90` against a fabricated `$100.00` ceiling. Observations carry a `unit` column; only `cents` renders as currency, so a header that arrives in dollars declares `unit: 'cents', scale: 100` on its `HeaderSpec` and is converted at parse. A new currency unit would be a third denomination every consumer has to learn — convert instead.
- **`finish_reason === 'length'` exempts a failure from the cooldown bench — and a reasoning model can spend a 215K-token prefill on hidden reasoning and emit nothing.** The same request retried three times at ~100K tokens each, metered as 1 request / 0 tokens. Only the *streaming* path shows it; non-streaming folds reasoning into `content`, which is why it looked model-specific. The exemption is now priced by `wastedInputTokens` and lifts once cumulative waste exceeds the budget, and failed attempts meter their tokens.
